# План разработки Shopify-приложения Bottle Deposit

## 1. Цель

Создать embedded Shopify app, которое автоматически назначает возвратный депозит выбранным товарам с водой.

Базовое значение депозита: **€0.10 за одну бутылку**. Значение редактируется в админке приложения.

Для подходящих товаров рядом с ценой должно отображаться:

```text
{{ price }} + 0.10Euro per bottle
```

Текст должен появляться во всех согласованных местах темы:

- карточки товаров на главной странице и в рекомендациях;
- карточки товаров в коллекциях и результатах поиска;
- страница товара;
- обычная корзина;
- cart drawer / mini cart;
- checkout, где Shopify позволяет управлять представлением строк.

## 2. Основные бизнес-правила

Товар получает депозит, если:

1. он содержит хотя бы один включающий тег **или** входит хотя бы в одну включающую коллекцию;
2. он не содержит исключающий тег;
3. он не входит в исключающую коллекцию.

Приоритет правил:

```text
Исключения > включения
```

Пример: товар находится в коллекции `Вода`, но имеет исключающий тег `19л бутылка`. Депозит не применяется.

Для MVP принимаем правило: **одна единица варианта в корзине равна одной бутылке**. Если в магазине продаются упаковки по 6/12/24 бутылки, до запуска нужно добавить к варианту поле `Количество бутылок в единице` и рассчитывать депозит как:

```text
deposit total = deposit per bottle × bottle count × cart quantity
```

## 3. Рекомендуемая архитектура

### 3.1 Компоненты

1. **Embedded admin app**
   - Shopify React Router app template;
   - App Bridge;
   - Polaris App Home web components;
   - форма настроек и Shopify Resource Picker для коллекций.

2. **Shopify Cart Transform Function**
   - выполняется на стороне Shopify;
   - проверяет теги и коллекции товара;
   - разворачивает подходящую строку корзины в основной товар и компонент депозита;
   - депозит становится реальной частью расчёта корзины и заказа, а не только визуальным текстом.

3. **Скрытый Shopify-продукт депозита**
   - создаётся приложением при первоначальной настройке;
   - название, например `Bottle deposit`;
   - один вариант с текущей ценой депозита;
   - не публикуется в канале Online Store и не должен продаваться отдельно;
   - используется Cart Transform как компонент подходящего товара.

4. **Theme App Extension и адаптер темы**
   - app embed загружает минимальный storefront-скрипт и стили;
   - app block используется там, где тема поддерживает блоки;
   - для цен в карточках, поиске, рекомендациях и нестандартном cart drawer потребуется адаптер под конкретную опубликованную тему;
   - eligibility и сумма передаются через Shopify metafields, чтобы витрина не обращалась к Render/Neon при каждом показе цены.

5. **Web application backend**
   - OAuth и Shopify session storage;
   - Admin GraphQL API;
   - сохранение настроек;
   - синхронизация metafields и варианта депозита;
   - обработка webhooks.

6. **PostgreSQL**
   - Neon Postgres;
   - хранит Shopify-сессии, настройки магазина, выбранные правила, состояние установки и журнал синхронизаций.

### 3.2 Почему депозит лучше сделать вложенным продуктом

Для MVP выбираем **вложенный компонент через Cart Transform `lineExpand`**.

Преимущества:

- расчёт выполняется Shopify и сохраняется при переходе в checkout;
- количество депозита связано с количеством товара;
- удаление основного товара не оставляет депозит в корзине;
- поддерживается accelerated checkout;
- компонент депозита можно показать отдельной вложенной строкой;
- депозит попадёт в заказ как компонент, что удобнее для учёта.

Не рекомендуется строить основную логику только на JavaScript, который добавляет отдельный товар через Ajax Cart API. Такой вариант уязвим для race conditions, удаления депозита покупателем, сторонних cart drawer, Buy Now и других способов обойти storefront-скрипт. У Cart Transform сейчас нет универсальной операции `lineAdd`, поэтому именно `lineExpand` является надёжной платформенной основой.

Ограничения Cart Transform нужно учесть отдельно:

- операции expand не применяются к строкам с selling plans/subscriptions;
- Create Order API и Order Edit поддерживаются не полностью;
- POS требует отдельной проверки и настройки `requiresComponents`;
- перед реализацией необходимо проверить совместимость с установленными bundle/subscription apps.

Документация: https://shopify.dev/docs/api/functions/latest/cart-transform

## 4. Настройки в админке

Создать страницу `Deposit settings` со следующими секциями.

### 4.1 Основные настройки

- переключатель `Enable bottle deposit`;
- сумма депозита;
- валюта: для первой версии фиксированная `EUR`;
- preview: `€2.50 + 0.10Euro per bottle`;
- статус скрытого продукта депозита;
- статус Cart Transform;
- кнопка сохранения;
- Save Bar и уведомление об успешном/неуспешном сохранении.

Сумму хранить в минимальных денежных единицах:

```text
10 cents, а не floating-point 0.10
```

### 4.2 Правила включения

- список включающих тегов;
- выбор одной или нескольких включающих коллекций через Shopify Resource Picker;
- отображение выбранных правил как removable chips.

Для тегов нужен autocomplete на основе Shopify Admin API, поскольку Resource Picker выбирает продукты/варианты/коллекции, но не теги.

### 4.3 Правила исключения

- список исключающих тегов;
- выбор исключающих коллекций через Shopify Resource Picker;
- явная подсказка: исключения всегда имеют приоритет.

### 4.4 Диагностика

- количество включающих и исключающих правил;
- дата последней успешной синхронизации;
- предупреждение, если app embed не активирован;
- ссылка, открывающая Theme Editor для активации расширения;
- тестовый выбор товара с результатом `Deposit applied / Excluded` и объяснением сработавшего правила.

## 5. Данные и конфигурация

### 5.1 Предварительная модель базы данных

#### `Shop`

- `id`;
- `shopDomain`;
- `installedAt`;
- `uninstalledAt`;
- timestamps.

#### `DepositSettings`

- `shopId`;
- `enabled`;
- `amountMinor` — по умолчанию `10`;
- `currencyCode` — по умолчанию `EUR`;
- `depositProductId`;
- `depositVariantId`;
- `cartTransformId`;
- `bottleCountMode`;
- timestamps.

#### `DepositRule`

- `id`;
- `shopId`;
- `effect`: `INCLUDE | EXCLUDE`;
- `resourceType`: `TAG | COLLECTION`;
- `resourceId` — GraphQL ID для коллекции;
- `value` — нормализованный текст тега;
- `label` — отображаемое имя;
- timestamps.

#### `SyncLog`

- `id`;
- `shopId`;
- `operation`;
- `status`;
- безопасное сообщение без токенов и персональных данных;
- timestamp.

Стандартная таблица Shopify session storage остаётся частью схемы.

### 5.2 Shopify metafields

Конфигурация должна дублироваться в app-owned metafields Shopify:

1. **Cart Transform owner metafield** — сумма, variant ID депозита, списки включающих/исключающих тегов и коллекций, а также variables для Function input query.
2. **App-data/shop metafield** — публично необходимая витрине конфигурация и версия настроек.
3. При необходимости **product/variant metafield** — количество бутылок в одной продаваемой единице.

Cart Transform может использовать variables для `hasAnyTag` и `inAnyCollection`; поэтому изменение выбранных правил не требует нового deploy функции.

Документация: https://shopify.dev/docs/apps/build/functions/input-queries/use-variables-input-queries

## 6. Логика применения депозита

Псевдологика функции:

```text
for each cart line:
  if line is not a product variant:
    skip

  included = hasIncludedTag OR inIncludedCollection
  excluded = hasExcludedTag OR inExcludedCollection

  if settings are disabled OR not included OR excluded:
    skip

  bottleCount = configured bottle count or 1
  expand line into:
    - original product component with original unit price
    - deposit component with fixed unit price
      and quantity = bottleCount per purchased unit
```

Обязательные проверки:

- функция не должна повторно обрабатывать сам продукт депозита;
- результат не должен удваивать депозит после обновления количества;
- сумма основного товара не должна изменяться;
- депозит должен корректно умножаться на quantity;
- исключение должно побеждать любое количество включающих правил;
- округление должно выполняться в minor units;
- при presentment currency нужно явно проверить требование бизнеса: показывать/взимать всегда EUR или конвертировать депозит в валюту покупателя.

## 7. Отображение на витрине

### 7.1 Формат

Первая версия выводит точный текст:

```text
{{ price }} + 0.10Euro per bottle
```

При изменении суммы в админке текст обновляется автоматически.

Рекомендуется сразу заложить локализуемый шаблон:

```text
{{ price }} + {{ deposit }} {{ currency_label }} per bottle
```

### 7.2 Способ интеграции

Theme App Extension не может гарантированно вставиться рядом с каждой ценой любой Shopify-темы: названия snippets, DOM и реализация cart drawer отличаются. Поэтому работа делится на два уровня:

1. **Базовое расширение**
   - app embed;
   - app block для product page;
   - storefront assets;
   - настройки текста и стилей.

2. **Адаптер опубликованной темы**
   - найти единый price snippet темы;
   - передавать в него текущий `product`/`variant`;
   - добавить вывод депозита после цены;
   - обновить карточки, search suggestions, recommendations, cart page и cart drawer;
   - подписаться на variant change и cart section re-render;
   - не показывать надпись исключённым товарам.

Нельзя считать требование «везде рядом с ценой» выполненным только после добавления app block на product page. Нужен аудит конкретной темы и отдельный regression checklist.

Документация Theme App Extensions: https://shopify.dev/docs/apps/build/online-store/theme-app-extensions/configuration

## 8. Webhooks и синхронизация

Минимальный набор:

- `APP_UNINSTALLED` — удалить/анонимизировать сохранённые данные и завершить сессию;
- `PRODUCTS_UPDATE` — актуализировать связанные данные и количество бутылок;
- `COLLECTIONS_UPDATE` — перепроверить правила коллекций, если используем материализованные product metafields;
- обязательные privacy webhooks Shopify.

Webhook должен:

1. пройти HMAC-проверку;
2. быстро сохранить событие/idempotency key;
3. вернуть `200 OK`;
4. выполнить тяжёлую синхронизацию асинхронно или через идемпотентный повтор.

У Shopify есть таймаут соединения около 1 секунды и общий таймаут около 5 секунд. Это важно для Render Free, который засыпает после простоя.

Документация: https://shopify.dev/docs/apps/build/webhooks/verify-deliveries

## 9. Этапы реализации

## 10. Матрица приёмки

### Правила

- только включающий тег → депозит есть;
- только включающая коллекция → депозит есть;
- включающий тег + исключающий тег → депозита нет;
- включающая коллекция + исключающий тег → депозита нет;
- включающий тег + исключающая коллекция → депозита нет;
- нет включающих правил → депозит не назначается;
- приложение выключено → депозит не назначается.

### Цена и количество

- 1 бутылка → €0.10;
- quantity 5 → €0.50;
- изменение настройки на €0.15 обновляет новую корзину и витрину;
- основной товар сохраняет исходную цену;
- удаление товара удаляет связанный депозит;
- изменение quantity синхронно меняет депозит;
- исключённый товар никогда не получает депозит.

### Витрина

Проверить надпись рядом с ценой на:

- homepage cards;
- collection cards;
- search results и predictive search;
- product page;
- featured product/recommendations;
- cart page;
- cart drawer;
- checkout;
- desktop и mobile;
- смене варианта;
- обновлении cart sections без полной перезагрузки.

### Совместимость

- обычная покупка;
- accelerated checkout;
- discount code и automatic discount;
- товар без остатка;
- multi-currency/Markets, если используется;
- subscriptions и bundles — ожидаемое ограничение или явное сообщение;
- uninstall/reinstall;
- недоступность Render/Neon не должна ломать уже опубликованную витрину или выполнение Shopify Function.

## 11. Риски и решения

| Риск | Решение |
|---|---|
| Универсального DOM/price snippet для всех тем нет | Поддержать текущую тему как отдельный адаптер и вести regression checklist |
| Покупатель удаляет отдельный депозит | Использовать Cart Transform `lineExpand`, а не только Ajax Cart API |
| Render Free спит и не отвечает webhook вовремя | Для разработки допустимо; для production использовать always-on instance или другой always-on hosting |
| Правила в БД и Shopify расходятся | Shopify metafield — runtime source для Function; транзакционная запись + reconciliation |
| Товар одновременно включён и исключён | Жёсткий приоритет исключений |
| Упаковка содержит несколько бутылок | Метаполе bottle count на variant |
| Multi-currency меняет €0.10 | До реализации зафиксировать правило конвертации и отображения |
| Deposit product попадает в каталог | Не публиковать в sales channels и исключить из поиска/рекомендаций |
| Скидки уменьшают депозит | Проверить discount allocation и при необходимости исключить deposit variant из discount logic |
| Неверный налоговый режим | Согласовать tax/shipping/returns с бухгалтером до production |

## 12. Definition of Done

Функция считается готовой, когда:

- сумма редактируется и по умолчанию равна €0.10;
- администратор выбирает включающие/исключающие теги и коллекции;
- исключения всегда имеют приоритет;
- депозит реально входит в сумму корзины и заказа;
- количество депозита соответствует количеству бутылок;
- требуемый текст отображается во всех согласованных price surfaces текущей темы;
- настройки не требуют redeploy приложения;
- отключение приложения прекращает применение депозита;
- webhooks идемпотентны;
- тестовая матрица пройдена на dev store;
- production не зависит от sleeping free instance для критических webhook-операций.
